# 设计范围、Section 与多页面 Prototype

用于读取多个页面、筛选状态、弹层或组件交互。Section 是设计范围，Prototype 是行为证据，HTML 是需要另外实现和测试的产物。不能由画板排列猜测连线，也不能把播放链接当成自动生成业务代码的接口。

## 学生准备与输入

建议把同一流程的页面整理到同一个 Section，完成 Prototype 连线并设置起点；单画板任务不强制增加 Section。确保当前连接的 Figma 账号能查看文件，不要求将私有文件公开，也不替用户修改分享权限。

提供含 node-id 的 Frame/Section 设计链接；有原型时再提供 Prototype 演示链接和要演示的 Flow 起点。说明原始 Frame 尺寸与期望展示尺寸；能从节点读取尺寸时自行读取，不重复索要已知值。图片/图标默认导出原始素材到本地 assets，保留裁切、透明度及节点映射。字体来源和使用权限另记录，不能因可读取而自动获得分发权。

可复制的输入模板：

```text
使用 $xiangsu100-figma-to-html，将以下 Figma 页面和交互链路还原为 HTML。
Frame 或 Section 设计链接：【填写】
Prototype 演示链接（已有时）：【填写】
目标 Flow / 起点 / 要演示的链路：【填写，已能读取时无需重复】
原始 Frame 尺寸：【可由 Figma 读取】
展示尺寸：【默认原始尺寸；如需适配请说明】
输出：【默认原生 HTML/CSS/JS；已有项目沿用其技术栈】
素材：【原始图片/图标保存 assets；另外需要单文件时请说明】
先列出范围内所有页面、节点 ID、尺寸和交互关系，再逐页还原并接通链路。
完成同尺寸截图、50%叠图、增强差异图，修正后再次截图对照。
交付入口、完整素材、链路测试记录和仍未还原/无法验证的部分。
```

示例材料中的 React + TypeScript 只是该示例的技术选择，不能覆盖本项目要求。已有工程保留构建工具、目录、依赖和代码规范，最小范围修改；不重建无关项目或格式化无关文件。

## 第一步：盘点页面与状态

1. 按用户提供的节点限定读取范围。Section 下枚举所有候选页面 Frame，包括分组中的页面，记录名称、节点 ID、尺寸、位置和展示顺序；不要把页面内部的 Auto Layout Frame 都当独立页面。先以结构缩小范围，再逐个取设计上下文和截图，避免首个 Frame 完成就停下。
2. 区分独立页面、弹层、组件变体和同页状态。筛选截图看起来像一张完整页面，也可能应实现为当前页面上的状态；以原型行为和图层证据决定，不能只看名称或遮罩颜色。
3. 保存页面清单，状态分为“已读 / 未读 / 来源不足”；另列实现和验证状态。Section 中暂未实现的页面不能从清单消失。节点排列仅表示展示顺序。
4. 连线指向 Section 外时单列目标与依赖。读取完成该链路所需且已授权的目标；不自动扫描整个文件。未知目标、删除节点、不可达页面、多个起点都需明确记录。

推荐项目内保存 `verification/pages.md` 与 `verification/flows.md`，这些含真实节点的记录留在项目，不放入公开 Skill 仓库。

## 第二步：读取并记录原型行为

先检查当前 Figma 工具是否能只读提取 Prototype。不要假设 design-context 摘要一定包含完整 reactions：

- 允许使用 Plugin API 的环境，可在指定范围读取 `PageNode.flowStartingPoints`、页面及后代交互节点的 `reactions`。保留触发节点 ID、trigger、完整有序 `actions`、条件与变量行为、destinationId、navigation、transition、滚动和组件重置设置；不要只读取第一条 action。旧接口只有 `action` 时按真实返回兼容，并记录接口差异。
- `flowStartingPoints` 有起点节点和名称；用户指定 Flow 时用该起点，不能固定用最左 Frame 或第一张截图。没有用户指定时按可读默认起点处理并说明。
- 工具未暴露这些属性时，用已授权的 Prototype 预览逐步检查热点、跳转、弹层位置、取消/返回、滚动与状态变化；只有播放截图不足以证明完整链路。
- 两条证据路径都不足时，继续可独立完成的静态页面，列出缺失关系，再向用户索要最小交互表或可读来源。“未读到连线”不等于“用户没连线”。不得凭布局补称原型行为。

每条关系至少记录：

| 起点状态 | 触发节点/操作 | 行为与目标 | 条件、顺序、动效/重置 | 证据来源 | HTML映射 | 实测结果 |
| --- | --- | --- | --- | --- | --- | --- |
| 列表 | 筛选按钮 / 点击 | 打开筛选弹层 | 关闭方式、背景交互 | reaction或预览记录 | 同页 dialog / 状态 | 待测 |
| 列表 | 某条目 / 点击 | 打开详情 | 是否保留滚动与筛选 | reaction或预览记录 | 路由 / 详情状态 | 待测 |
| 详情 | 返回按钮 / 点击 | 返回来源状态 | 不能假设总回首页 | reaction或预览记录 | 历史栈与状态恢复 | 待测 |

一个 trigger 可能顺序执行变量赋值和导航，也可能有条件分支。没有实际走过的条件不能标成已测试。

## 第三步：映射为可运行的 HTML

| Prototype 行为 | HTML 中的实现和核对 |
| --- | --- |
| Navigate | 页面路由或同文档状态；入口、目标和返回一致 |
| Back | 记录来源和历史，不把所有返回按钮硬编码到首页 |
| Open/Swap/Close overlay | 同页弹层及弹层栈；位置、遮罩、外部点击、关闭和滚动锁定按原型证据 |
| Change to | 组件状态/变体；保留选中、禁用、文案和视觉状态 |
| Scroll to | 正确的滚动容器、锚点、固定区与偏移 |
| URL | 明确外链行为；未实际打开时单列未验证 |
| 变量 / 条件 / 动效 | 保留执行顺序、条件和计时；Smart Animate等不能原样实现时说明具体近似范围 |

先完成所有目标页面和关键状态的静态还原/截图修正，再接通交互；这是实施顺序，**不是只交第一轮静态页面**。除非用户明确只要静态稿，最终仍须完成范围内链路。列表数据、筛选选中值、已领取状态和滚动位置是否保留或重置，应按证据实现，不统一套一个规则。无业务服务时标明本地模拟。

原生多页面可交付目录包和入口；需要单文件时可用同文档页面状态/hash路由并内嵌依赖。`bundle_html.py`只打包当前文档的受支持资源，不会把相互链接的多个HTML自动合成一个App。目录模式在解压目录测完整路径；单文件必须在空目录和无基址预览重走链路，不能只确认首页能打开。

验收使用原始 Frame 对应CSS视口，不用根容器 `transform:scale()` 或 zoom 冒充精确还原。学生查看对照页时可单独缩放预览，但需标明展示比例并保留原尺寸证据；窄屏适配则依据约束另测。各页尺寸不同应分别记录并分别截图，不能统一拉伸到一种尺寸。

## 第四步：逐状态对照，再走整条链路

逐页执行 [verification-and-delivery.md](verification-and-delivery.md) 的叠图修正；页面/弹层/选中态/返回态分别建立截图对应关系。若Figma只提供独立弹层小Frame，只能与同范围裁切比较；不能拉伸弹层原图到整个页面，也不能把合成全屏图冒称Figma原始导出。

从每个范围内起点走通目标分支，检查正常路径、取消、返回、重复打开/操作、滚动容器和状态恢复。有设计依据的浏览器后退、刷新或深链接也应验证；未定义部分不要扩展成新功能。按每条关系记录“已实现 / 已实测 / 未验证及原因”，页面视觉通过不等于交互链路通过。使用脚本时可配置顺序动作和关键状态截图，见验证说明；脚本不自动推断Prototype图，也不证明所有分支已覆盖。

## 官方依据

- [Reaction](https://developers.figma.com/docs/plugins/api/Reaction/)：trigger与有序actions；旧action字段已弃用。
- [Action](https://developers.figma.com/docs/plugins/api/Action/)：导航、返回、弹层、变量与条件动作。
- [flowStartingPoints](https://developers.figma.com/docs/plugins/api/properties/PageNode-flowstartingpoints/)：页面中的原型起点。
